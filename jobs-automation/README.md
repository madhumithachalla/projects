# JOBS engine (v8.0)

A deterministic core for the JOBS automation: it decides, tracks and drafts. Claude (Cowork routines, Gmail connector, browser) does the searching, sending and applying, and must pass the gates here first.

```
python3 -m unittest discover -s tests      # 56 tests, standard library only
python3 -m jobsys seed                      # write data/tracker.json (27 roles known on 08/10/2026)
python3 -m jobsys classify ad.txt --company X --title Y
python3 -m jobsys ingest ad.txt --company X --title Y --url URL --found-on Indeed
python3 -m jobsys list [--status "Preview Sent"] [--category "Job board"]
python3 -m jobsys status J0033 Approved     # validated, Melbourne-timestamped
python3 -m jobsys can-submit J0033 [--quality-gate --calendar-clear --stop account]
python3 -m jobsys previews                  # out/previews/<id>.json  {to, subject, body}
python3 -m jobsys build                     # dashboard/data.js, then open dashboard/index.html
```

## What it enforces (each rule has tests built from real ads)

| Rule | Where |
|---|---|
| Closing date is shown when the ad has one, otherwise "not listed", priority NORMAL, and the role is still tracked and emailed | dates.py, rules.py, preview.py |
| Skip: citizen/PR only, NV1/NV2/Baseline/AGSVA, international applicants not supported, 5+ years (or 3-5), senior title, unpaid, undergraduate only, SAP/Ericsson/Charles River/JDE/pen testing/FIFO, required language not on record, not an IT role, already closed | rules.py |
| Inclusive wording is not a restriction ("right to live and work", a non-discrimination footer, "citizen ... or a non-Australian citizen holding a valid visa") | rules.py |
| Flag, never answer: sponsorship "now or in the future", full working rights, driver's licence, faith ethos, on-call, 48 hours per fortnight for full-time roles, stale posting | rules.py |
| A skill the ad asks for that is not on the record is listed as "NOT on your record, never claimed" | rules.py, profile `not_claimable` |
| Dedupe by company + title and by URL, plus the ruled-out list (this blocks ADAPTOVATE) | tracker.py, data/ruled_out.json |
| A role needs a sent preview before it can be Approved; APPROVE ALL touches only sent previews; transitions are validated and stamped in Melbourne time | tracker.py |
| Silence is never approval. Only Approved roles may be submitted, except the closing-soon lane (within 24 hours, quality gate passed, calendar clear, no stop condition). A role with no closing date can never use the lane | gates.py |
| Two fields: portal (Job board, Graduate platform, Employer career site, Government, University / education, Health / aged care, Recruiter / agency, Email apply, Gmail alert) and employer type | portals.py |
| No em or en dashes in any preview | preview.py |

## What it deliberately does not do

- It never sends email, submits an application, creates an account, types a password or solves a CAPTCHA. The previews it writes are sent by the Gmail connector in a Claude routine; applications are submitted by the browser only after `can-submit` says ALLOWED.
- It does not search job sites. The routine searches (Indeed connector, web, browser) and pipes each ad's text into `ingest`.
- It does not build resumes. The pack builder in your master document still does that (see `docs/BUILDER_FIXES.md`).
- The dashboard is read-only. "Copy reply" puts `APPROVE J0036` on the clipboard for you to paste into your reply or tell Claude.

## Honest limits

- Rules are regular expressions over the ad text. They are strict where the cost of a wrong yes is high (citizenship, clearance, years) and they flag instead of deciding where an ad is ambiguous. New phrasing will slip through: add the sentence to `tests/test_rules.py` first, then fix the rule.
- Skill matching is a keyword vocabulary in the profile, not understanding. It lists what the ad names that is or is not on the record.
- Seeded roles (J0033 to J0052) carry hand-written flags from the 08/10/2026 emails because the ad text was not saved. New roles get flags generated by the rules.
- The Indeed link (to.indeed.com) hides the employer's real apply page, so the portal note says "not checked yet".

## Students (next)

Everything personal lives in `profiles/<name>.json` (facts, skills, not-claimable list, recipients, visa line, rules thresholds). A student gets their own profile and their own tracker file; the rules, gates, portals, previews and dashboard are shared code. Before offering this to students you need: per-student data isolation (one tracker file or database per student), their own Gmail or no email sending, consent and privacy handling for CVs and visa details, a profile-intake form that records only what the student confirms (the `not_claimable` list is what stops invented skills), and a safe default for visa and work-rights wording. Start with yourself, then one friendly student, before opening it up.
